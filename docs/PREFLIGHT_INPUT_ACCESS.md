The remaining **46 exact paths, byte sizes, SHA-256 hashes, categories, and routes** are listed individually in `repro/preflight_missing_46.csv` (manifest SHA-256 `3f06df50830eb45f549be5651fa01302a3d7a66c4dc3acd0009f0f31c7b7baf9`). They total a historical audit snapshot, not 46 unreported numerical inputs. A scan of the frozen Phase 3 Python scripts found these paths used directly only by `f3_preflight.py`'s strict 161-file hash gate. The E1/E2/E3 scientific computations use separately documented hourly/minute, GFZ, DIFI and monthly-matrix inputs. The strict gate still requires the historical bytes; this distinction does not waive it.

## Assemble an explicit input root

1. Start with the repository checkout at the commit cited by the manuscript. Obtain the 79 externally sourced archives/files named in `scripts/00_download/download_manifest.csv` from WDC Edinburgh/BGS, GFZ Potsdam and Mendeley Data under their terms. `scripts/00_download/download.py --verify-only` checks the recorded SHA-256. The two historical WDC tabular-hour responses above are **additional** entries in the 46-file inventory; the complete corrected response is also in the 79-source downloader manifest.
2. Reconstruct the extracted `phase2a/raw/` tree using the original G0 inventory procedure, and retain the author's G0 manifest/validation bytes when satisfying the strict preflight. Supply the 2018 hourly/GFZ sources in `phase3/raw/` from the downloader manifest. The 42 Phase 1 minute ZIPs form `audit_sq_wdc/cache/`; the author's original-project `freeze_task1.py` documents the `audit_final/dataset_freeze.json` freeze. That Phase 1 script and its prior QC outputs are not part of this checkout and must be obtained with the author audit snapshot when reconstructing the strict tree. Keep the recorded minute-archive hashes. Newly generated freeze metadata may differ from the historical hash and must be labeled as a new snapshot.
3. Add the 46 historical audit inputs at the **relative paths** in `repro/preflight_missing_46.csv` from an authenticated, rights-reviewed author snapshot. The CSV explains which four numeric derivatives can be rebuilt and which historical records require the original files. A reviewer does not need the author's personal drive letter: only an assembled `INPUT_ROOT` with this relative layout.
4. Verify the missing files and run the portable wrapper at separate roots:

```text
python repro/make_preflight_inventory.py --source-root INPUT_ROOT --repo-root REPO_ROOT --output INPUT_ROOT/preflight_missing_46_verified.csv
python repro/portable_pipeline.py prepare --input-root INPUT_ROOT --output-root OUTPUT_ROOT
python repro/portable_pipeline.py run --output-root OUTPUT_ROOT --workers 8 --stages inventory,ssb,e1_holdout,e1_evaluate,e1_secondary,e2_development,e2_holdout,e2_evaluate,e3b_prepare,e3,e3_summary,figures
```

`prepare` verifies every staged file and the unchanged 161-file frozen gate. It copies the authenticated GFZ 2018 quiet-day file to the frozen E1 reader's legacy lookup path **inside `OUTPUT_ROOT` only**. Its `reproduction_setup.json` records both roots, input-manifest hash, source commit, and adapter hash. Stage logs record commands, exit codes, durations and log hashes. The first complete run of this final wrapper after the GFZ adapter is separately identified in the audit closure; it must not be conflated with the earlier recovery-and-correction rerun.

The public repository by itself cannot pass the strict preflight. The 46-file manifest is an exact access map, not a claim that the omitted records have been published. Replacing the strict historical gate with a newly scoped gate would require a documented new analysis version and is outside this finalization.
